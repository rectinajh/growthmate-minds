# 演示 Runbook（黑客松现场）

## 目标

在 2 分钟内让评审看到：**记得住昨天、会自动做、有创作者的声线/语气**。

## 前置

- `.env` 已配好 `MINDS_BUILDER_API_KEY`。
- hellominds.ai 控制台已配置 Telegram 集成（如需现场推送）。
- 提前执行 `npm run onboard && npm run build`（演示时只运行验证命令，避免等待构建）。

## 分场景脚本

### 场景 0：接入（约 10 秒）
```
npm run list
npm run show -- <mind-uuid>
```
旁白：GrowthMate 是常驻 Minds 代理，拥有自己的身份、长期记忆和钱包。

### 场景 1：连续（约 30 秒）
```
npm run memory -- "@kiki 在最新视频下评论：上期那个汤底配方能出个详细版吗？"
npm run memory
```
预期输出：昨天谁最活跃 / 我答应过谁什么 / 待转化名单。重点展示「它记得 @kiki 上周问过增肌餐」。

### 场景 2：自主（约 30 秒）
```
npm run briefing
```
预期输出：昨日增长简报（新增粉丝与互动 → TOP 5 → 待跟进 → 选题建议），每条带「为什么 + 建议动作」。现场可切换到 Telegram 展示主动推送。

### 场景 3：声线/语气（约 30 秒）
```
npm run followup
```
预期输出：Kiki / Leo 的「待确认草稿」，引用历史互动、用创作者语气。若现场有 TTS 连接则播放语音；否则展示文字草稿 + 预录声线（见 `tts-decision.md`）。

### 收尾（约 10 秒）
字卡：**涨粉参谋：记得住 · 会自动 · 有你的声音**。

## 应急

- 回复超时：`npm run history` 查看是否已返回。
- 简报无数据：强调「诚实降级」——明确标注待接数据源，只报已有记忆。
- Telegram 未推送：用对话内提醒代替，并说明这是集成配置项而非能力缺失。
